現在的方向

  • ① 在做什麼 C++ 手寫離線渲染器（路徑追蹤）
    2026-08-14 定案 C++ 路徑追蹤 離線渲染
    • 一切都是自己寫的 —— 從 main() 開始，最外層迴圈是自己的 for y / for x。沒有引擎、沒有框架、沒有「等別人來呼叫我」
    • 零依賴 —— 一個 .cpp 加一個單檔頭圖片輸出庫。不裝 CMake、不裝 vcpkg，一次只加一樣東西
    • 日常只開 Visual Studio：寫 Renderer.cpp → Ctrl+F5 → 看 out.png
    • 目前進度：環境架設中，第一張圖還沒出來
  • ② 為什麼是這條 圖就是裁判，而且 bug 有形狀
    • 語言優先。C++ 是所有語言裡最喜歡的一個。排斥 C# 的真正原因是儀式性語法，還有「主迴圈不屬於自己」—— _Ready() 是引擎呼叫你，不是你在跑
    • bug 有形狀。太暗＝少了 gamma；表面黑點＝射線自交；孤立亮點＝高變異數路徑；顏色整個翻掉＝RGB/BGR 寫反。錯誤可以用眼睛演繹，不必亂試
    • 不做遊戲。離線渲染的主場是電影特效、動畫、工業與科學視覺化。它追求物理正確，一幀算幾小時也可以 —— 跟遊戲的 16 毫秒妥協文化是相反的價值觀
    • 又深又難，人又少。渲染方程式（Kajiya 1986）一行寫得完，整個領域四十年都在解它
  • ③ 下一步 先讓第一張圖出來，再一路走到會反彈的光
    • 裝 VS 的 C++ 工作負載，跑出第一張 256×256 漸層 PNG。這一階不學渲染，只是確認「程式跑完 → 資料夾出現一張圖」這條路是通的
    • 射線與相機 → 球的求交 → 法線著色。驗收是「畫面中央出現一顆有立體感的彩色球」
    • 真正的分水嶺在漫反射：第一次出現「沒有公式可以直接算，只能取樣很多次求平均」。柔和陰影跟地面滲上來的顏色，沒有任何一行程式碼在算它們 —— 它們自己長出來
