# 2026-08-24 — 工作回報 #7：又一天後再換引擎 → C++ + raylib（方向第三次沒變，工具第三次換掉）

## 今天讀/做了什麼

**昨天從 Godot 換到 Unity。今天從 Unity 換到 C++ + raylib。方向仍然沒動。**

- 方向還是 **湧現模擬（Emergent Simulation）** —— 寫規則，讓自主單位在規則下自己活，長出算不到的東西
- 換掉的是引擎：**Unity 6.5 + C# → C++20 + raylib 6.0 + MSVC**
- 工作區從 `D:\Swarm` 搬到 `D:\raylib`

**換的三個理由（自己覺得站得住的那些）**

- **(1) 語言稅。** C++ 是我最強的語言（CP 出身）。Unity 那條線上我同時在付**語言稅 + 引擎 API 稅**，兩份都要付。raylib 那條兩個都接近零 —— 認知預算全部花在模擬規則本身。對一個實作頻寬一年只有 120 天的人來說，認知預算才是最稀缺的資源，不是時間
- **(2) 沒有第二個程式。** 昨天實測踩到 VS 跟 Unity 的 COM 交接爛帳（我的原話：「unity 跟 vs 協作到底是怎樣 沒有用啊」）。raylib 從結構上刪掉這個坑：**沒有編輯器、沒有場景檔、沒有 `.meta`、沒有 `Library` 快取、沒有匯入管線、沒有 domain reload、沒有「Play 當中調的參數停止會消失」**。整個世界只有一個編輯器加一個終端機
- **(3) 立即模式跟湧現模擬同構。** 這條是今天才想清楚的：

  |  | 保留模式（Unity / Godot / DOM） | **立即模式（raylib）** |
  |---|---|---|
  | 世界怎麼存在 | 物件有身分，引擎替你保存，你去修改它 | 每一幀從零說「在這裡畫一個圓」 |
  | 引擎維護什麼 | 一棵樹：走訪、剔除、排序、批次 | 沒有樹 |

  我的蟻群骨架是「每幀 for 每一隻蟲：感測、決策、移動；再 for 每一隻蟲：畫一個點」。**這本來就是立即模式的形狀。** 用保留模式引擎跑它，等於在一個為「一千個各自有身分、有生命週期、有元件的物件」設計的系統上，跑「三十萬個沒有身分、可以隨時整批丟掉的數字」——**抽象的成本付了，好處一個都沒拿到**
- 更深一層：保留模式說「東西有身分，你去修改它」，立即模式說「狀態是一坨數字，規則每幀重算全世界」。**第二種正是元胞自動機、boids、粒子系統的世界觀 —— 個體沒有特權，規則才有。** 我的方向叫「我不擺內容，我寫規則」，立即模式就是這句話的技術形態

**環境：這次真的是零安裝**

- 編譯器 **MSVC 14.51** 和 **CMake 4.3.1** 都是 Visual Studio 2026 Community **自帶的**，沒有為了 raylib 裝任何新軟體
- raylib 6.0 原始碼放在 `vendor\raylib\`，離線可建置
- 實測數字（之後拿來對照）：

  | 項目 | 數字 |
  |------|------|
  | 第一次設定（含從原始碼編整個 raylib） | **約 90 秒** |
  | **改一行 `.cpp` 重建** | **3.3 秒** |
  | 執行檔（Debug） | 1.9 MB |
  | VS 從雙擊到方案載入 | 10 秒 |

- 另外 raylib 可以用 emscripten 編成幾百 KB 的網頁 wasm。**「做完 → 公開」的距離被壓到最短** —— 這一項是 Unity WebGL（20–50 MB 加載入條）給不了的，而我本來就有這個網站

**★ 今天真正有價值的產出：把「一直往下鑽」拆成三種**

換到 C++ 之後最誘人的念頭是「一路往下鑽」。但那個詞其實是三個完全不同的方向，而且適配度相反：

| 鑽法 | 具體長什麼樣 | 間接性 | 歷史證據 |
|------|-------------|-------|---------|
| **A. 實作層** | spatial hash、四元樹、SIMD、多執行緒、記憶體池 | 中 | 未測。**只有被模擬逼出來才安全** |
| **B. 領域層** | 蟲加天敵 → 分工 → 基因 → 演化 → 生態自己長 | **高** | ✅ 粒子系統贏在這裡 |
| **C. 底層層** | 丟掉 raylib，自己寫 OpenGL / 軟體光柵 / platform layer | **零** | ❌ **這就是 raytrace，我只活了六天** |

- **A 的判準很細：**「naive O(n²) 實際跑不動了，所以我寫空間分割」→ 安全，痛驅動的。「我先把空間分割寫好，之後會用到」→ 危險，那是設定摩擦的高級形態
- **而 raylib 的文化引力正好指向 C。** 它的「no dependencies」信條、周邊的 Handmade Hero 傳統、社群裡大量「我把 raylib 換掉自己寫了 platform layer」的貼文 —— 整套價值觀都在把人往「自己寫底層」拉。**這不是可能性，是重力：不做任何事就會被拉過去**
- 對照一下：**Unity 的重力指向資產、Prefab、動畫、手擺內容**（我的表上寫著「適配度低，刪除」）。兩個引擎的重力都不指向靶心，差別在於**我對 Unity 的重力有免疫力**（本能覺得手擺很無聊），**對 raylib 的沒有** —— 因為它偽裝成「技術深度」，正好餵我的傲氣
- 所以記一條判準下來：**每次想往下鑽，先問「這是模擬逼我的，還是我想看底層」。後者就停**

**一個舊規則被推翻：位置類資料**

- Unity / Godot 時期的規則是「一律做成場景物件，用滑鼠拖，**絕對不要用字串找節點**」
- 今天想清楚：**那條規則的病因不是「不能拖」，是「同一份資料存在兩個地方」** —— 場景樹一份、程式碼一份，腦中要同時維護兩張圖，對不上時編譯器不會擋。我一直說的「寫 code 跟擺物件不相容」就是這個
- **raylib 沒有場景檔，所以這個病從根源消失了。** 巢穴就是 `Vector2 nest = {32, 18};` 一行，**只有一份真相**
- 代價是不能用滑鼠擺。但那個代價很便宜（二十行程式碼就能做「左鍵點 → 印出座標」），而且反過來拿到 Unity 給不了的東西：**布局是純文字，可以進 git、可以 diff、可以手改**

**C++ 最不友善的那一面，跟它的解藥**

- C++ 沒有例外訊息、沒有堆疊追蹤。陣列越界不會報錯，**沉默當機，或更糟：不當機但數值悄悄變垃圾**。這對我這種「恨只能亂試的 debug」的人是直球對決
- 解法不是毅力，是工具：**AddressSanitizer**。實測同一個故意寫的越界：

  | 建置 | 我看到的 |
  |------|---------|
  | 一般建置 | **視窗閃一下就沒了，離開碼 3，零訊息** |
  | ASan 建置 | 下面這段 |

  ```
  ERROR: AddressSanitizer: heap-buffer-overflow
      #0 in main   src\main.cpp:7        ← 讀壞的是這一行
  0 bytes after 1200-byte region         ← 超出去多遠
  allocated by thread T0 here:
      #1 in main   src\main.cpp:4        ← 記憶體是在這裡配置的
  ```

- **這就是「可觀測的中間狀態」跟「只能亂試」的差別。** 一次告訴我三件事：哪一行讀壞、超出多少、記憶體是誰配置的。所以在 C++ 這條線上，**ASan 是必需品不是奢侈品，第一天就要開**

## 下週開始預計做什麼

- **把蟻群用 raylib 重寫一遍，當對照實驗。** 規則已經懂了，成本只有幾小時。要量三個東西：

  | 要量的 | 為什麼 |
  |--------|-------|
  | 實際冷啟動幾秒 | 唯一該拿來評估工具的指標，**實測不是猜** |
  | 沒有 Inspector 滑桿之後，調 `Decay` 變好還變壞 | `Decay` 是整個系統的甜點旋鈕 |
  | **有沒有一次想「我來自己寫個視窗層」** | **上面那條文化重力的測試** |

- **這次重寫不算進 `E10`** —— 那一格已經被蟲道填了。它是量數據，不是做系統
- **然後才是真正該做的那件事：轉 `Decay`。** 太小 → 蟲道永遠不消失，食物早就吃完了蟲還在跑舊路；太大 → 蟲道還沒成形就沒了。它就是「探索 vs 利用」的旋鈕，那個甜點要用眼睛找。**這件事三天前就能做，不需要任何引擎知識**
