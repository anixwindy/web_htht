# 2026-08-09 — 工作回報 #2：方向盤點 → 定案（C# + Godot 3D）

## 今天讀/做了什麼

**上午（分析）**

- 把 code 方向做了一次完整盤點，用自己的條件逐條篩
- 排除：遊戲、圖形／光追、網路、前端、資安、嵌入式、CAD、蒙地卡羅／統計、混沌、CP／Project Euler
- 也排除：效能工程（不喜歡硬體）、SAT 求解器（教材少、編碼要構造）、路徑規劃、編譯器（對「電腦系統本身」沒感覺）
- 確認的紅線：連續數學、空間旋轉、排列組合（構造）、黑盒工具、要自己想主題
- 確認的強項：方程式／代數操作、貪婪（交換論證）、比較靜態分析（差分）、概念連連看、現場推公式不背
- 結論：**程式對我是工具，不是題材。** 之前一直在「以電腦為研究對象」的領域裡找，框架本身錯了

**下午（動手，推翻上午）**

- 停止分析，改成一個一個實際跑：Python 的 1A2B 求解器與反作弊沙盒 → C++/raylib 的貪食蛇與 3D 地形 → 最後裝 Godot 4.7 跑起一個 3D 世界
- 結果推翻上午那條「排除遊戲」：**我排除的其實是「2D 畫面很醜」和「調手感」，不是遊戲本身**
- 關鍵發現：**3D 的視覺品質來自光照／材質／後處理，那是程式，不是手繪。** 對不會畫畫的人，3D 比 2D 友善得多
- 也弄懂了為什麼第一版 3D 看起來「沒有太陽」：俯視角看到的全是方塊頂面，法線一致 → 光照對比為零。**對比來自法線差異，不是來自光源存在**
- **定案：C# + Godot 4，做程序生成的 3D 開放世界。世界用程式碼長出來，不用滑鼠擺**
- 環境到位：VS 2026 + .NET SDK 10 + Godot 4.7.1 mono。在 VS 按 F5 直接跑遊戲，中斷點可用，全程不必開 Godot 編輯器
- 第一個能跑的東西：`FastNoiseLite` fBm 生成 32×32 地形（水／沙／草／岩／雪）、自由飛行相機、方向鍵即時轉太陽看影子掃過去
- repo：`github.com/anixwindy/C_game`

## 卡關點

- 上午卡在：方向仍未定，傾向數學（代數／邏輯側）
- 上午的真正卡點寫的是「**分析已到解析度上限**：三個月、冠軍換四次、零行 code。剩下的資料只能靠動手拿」——**下午就是照這句做的，而且它是對的**。三個月分析換不到的答案，五個小時動手換到了
- 上午擔心的「數學自學沒有裁判」，在遊戲方向下自動消失：**畫面就是裁判**。跑不跑得動、好不好看，眼睛直接判，不需要別人背書
- 新的卡點換成工具面：Godot 編輯器 + Visual Studio 兩個介面一開始很混亂，搞不清楚「到底在哪裡寫程式」
  - 已解：場景檔只留一個空節點，世界全部用 C# 建。**Godot 退化成一個被 VS 叫起來的執行檔**，日常只有一個介面
