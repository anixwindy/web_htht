# 2026-08-20 — 工作回報 #4：六天後再次推翻定案 → 競技程式設計（CP）

## 今天讀/做了什麼

**上午（推翻 #3，並且第一次講清楚「為什麼是這個」）**

- 上一篇 `#3` 定案的 C++ 離線渲染器維持了 **六天**（前一次 C# + Godot 維持五天）。這次推翻的理由不是渲染器不好，是終於找到一個比「題材」和「語言體感」都更準的自我描述
- **「鏈」偏好模型**：從四個維持了 7–11 年的嗜好裡歸納出同一個形狀 —— 爐石的 OTK combo、西洋棋的開局準備、roguelike 的殺招組合、1A2B。共同點是：**一條從初始狀態出發、把對手所有可能回應都吸收進去、最終收束到我要的終局的路徑**
- 這個東西在賽局論裡有精確的名字：**必勝策略（winning strategy）**。它不是比喻，是同一個數學物件
- 由此得到一張可以直接拿來排課的表 —— **題型適配度**：

  | 題型 | 鏈的形狀 | 適配度 |
  |------|---------|--------|
  | DP | `f[i]` 由 `f[i-1]` 決定，鏈的極致形式 | 極高 |
  | 構造題 | 直接設計一條路徑並證明它總成立 | 極高 |
  | 賽局論（Nim / SG） | 字面上就是必勝策略 | 極高 |
  | 貪心 + 交換論證 | 證明任何其他鏈都能換成我的鏈而不變差 | 高 |
  | 圖論最短路 / 拓樸 | 路徑本身就是鏈 | 高 |
  | 資料結構（線段樹、BIT） | 沒有鏈，是「維護一坨東西」 | 中低 |
  | 大量模擬 / 實作 | 沒有鏈，純體力 | 低 |

- 同時把偏食的代價算出來放在檯面上：**只吃愛吃的那四類，可玩題數約 1,100 題，rating 大約卡在 1500**。要不要逼自己吃資料結構是之後的決定，不是現在的
- 另一條更長期的：**兩種樂趣**。學習型（「哦，還有這招」，靠 editorial 外部供給，**會枯竭** —— 核心技巧只有約 250 個，3–5 年）vs 建構型（「我自己拼出了這條鏈」，來源是自己，不枯竭）。結論是一句話：**題庫不會空，但驚訝會空**
- 為此設了一個儀器：**`N10` 儀表板** = 每 10 題產生的**新**名字數，每 50 題算一次。大於 5 是拓荒期／2–5 建庫期／0.5–2 收斂期／小於 0.5 是模板窮盡，該從學習型切到建構型。它的價值在於把「會不會膩」這個模糊焦慮變成一個可讀的數字，而且每一格自帶處方

**下午（工具鏈盤點，結論是零安裝）**

- 全部現成，一個東西都不用裝：**CLion**（資料夾名寫著 `CLion 2025.3.1`，但 `build.txt` = `CL-262.8665.321` = **實際是 2026.2**，原地升級沒改資料夾名）、**MSYS2 UCRT64 g++ 15.2.0**、**GDB 17.1**、**CLion 內附的 CMake 4.3.1 + Ninja**
- 拆掉一個誤判：原本以為裝 Visual Studio 2026 把 CMake 刪掉了。**不成立** —— CMake 從來不在 PATH 上，`where cmake` 找不到被誤讀成「被刪了」。實測 `toolchains.xml` 時間戳仍是 2026-01-08，**VS 對 CLion 零影響**。守住「絕不把 MSVC 路徑寫進系統環境變數」這條紅線是有回報的
- 專案模型定案：**一個 `.cpp` = 一個執行檔**。`CMakeLists.txt` 用 `file(GLOB ... CONFIGURE_DEPENDS)` 掃根目錄，丟 `007.cpp` 進去存檔，右上角就自動長出 `007` target，**不用手動 Reload**。六個旋鈕集中在第 13–47 行
- **實測發現這台機器沒有 sanitizer**：MSYS2 UCRT64 的 GCC 不附 `libasan` / `libubsan`（`ucrt64\lib\libasan*` 根本不存在），`-fsanitize=address,undefined` 直接連結失敗。意思是**網路上抄來的 CP 編譯指令有一整類在這台機器上跑不起來**
- 替代方案實測，三個缺口分別補：

  | 缺口 | 補法 | 實測 |
  |------|------|------|
  | signed 整數溢位 | `-ftrapv`（Debug 專屬，預設 ON） | `int sum` 累加爆掉 → exit code 3，不印錯的答案。**編譯時間增加 0 ms** |
  | STL 容器越界 | `-D_GLIBCXX_DEBUG` | 直接印 `out-of-bounds index 10` 和行號 |
  | **原生陣列越界** | 改用 `array` / `vector` | `int a[10]; a[50]=7;` 完全靜默；`array<int,10>` 立刻被抓到，**效能完全相同** |

- 驗證分三層並標清楚現況：**L1**（編譯器警告 + `_GLIBCXX_DEBUG` + `-ftrapv`，抓「寫錯了」）已備妥；**L2**（對拍，抓「**想錯了**」）**還沒做**；**L3**（sanitizer，抓堆積越界）缺，優先度最低。CP 的 WA 裡「想錯了」佔壓倒性多數 —— **所以下一個工具投資是對拍腳本，不是裝 clang**
- 各 judge 的 C++ 版本查了一輪（CF 主流 G++20 / gcc 13.2、AtCoder gcc 12.2），附一個**單向的坑**：本機 gcc 15.2 比所有 judge 都新，**本機編得過的東西 judge 上可能還不存在（CE），反過來不會**。標準訂在 20 是保護不是保守
- 工作區從 `D:\Render` 搬回 `D:\Cthis`，舊的設定檔降級成指路牌；新 repo `github.com/anixwindy/CP_now`（舊的改名保留為 `old_C_Rendering`，不動不刪）；`push.bat` 一鍵上傳；`NOTES.md` 重建成 CP 帳本（四行複盤格式 + `N10` 表）

- **圓心漂了**：VS vs CLion → CMake → sanitizer → bat 腳本 → 網站文案。繞圈本身是暖機不是拖延（這是自己的學習模式），但這一輪繞的全是工具不是主題。好消息是工具真的完成了、沒有理由再回來繞；**壞消息是這種「完備感」本身就是一種拖延的獎勵**

## 下週開始預計做什麼

- 先把 `001.cpp` 補成一個真的能編的最小模板，跑通整條路：**貼題目 → Shift+F10 → sample 對得上**。驗收就兩件事：**exit code 0**、輸出跟 sample 一字不差。順便量一次冷啟動延遲（從「我想寫這題」到看到第一個 sample 結果），**超過 90 秒就不會開題**，那是唯一該拿來評估工具的指標
