# 2026-08-23 — 工作回報 #6：一天後換引擎 → Unity（方向沒變，工具換掉）

## 今天讀/做了什麼

**這次跟前五次不一樣：換的是工具，不是方向。**

- 方向仍然是 **湧現模擬（Emergent Simulation）** —— 寫規則，讓自主單位在規則下自己活，長出算不到的東西。這一條沒動
- 換掉的是引擎：**Godot 4.7.2 + C# → Unity + C#**
- 昨天才把 Godot 環境架完（零安裝、離線可建置、蟻群跑得起來、A/B 數據量過）。**今天就換掉了**

**換的理由不是「Unity 功能比較多」，是一個更精確的東西：翻譯稅**

- 先把摩擦拆成兩種，它們不是同一件事：

  | | 等待稅 | **翻譯稅** |
  |---|---|---|
  | 單次代價 | 幾秒 | **幾十分鐘** |
  | 會不會打斷思路 | 不會 | **會，硬中斷** |
  | 你在做什麼 | 等 | **在做別人的事**：找資料、比對版本、翻譯語法 |

- 之前一直把重點放在「冷啟動幾秒」，那是抓錯軸。**真正致命的是第二種** —— 因為我是極端長心流體質（連續 12 / 18 / 24 小時那種），重建心流的成本很高，而翻譯會硬中斷它
- 我的原話：**「時間要花在『我腦中有 A → 想想怎麼實現 A』，不是這裡又怎樣、那裡又怎樣、翻譯 code、找資料。」**

**Godot + C# 的翻譯稅是雙重的**

- **語言層**：找到的範例九成以上是 GDScript，要翻成 C#。命名慣例還不一樣（`snake_case` → `PascalCase`），signal 和單例的寫法也不同
- **版本層**：Godot 3.x → 4.x 大量 API 改名或消失，網路上還有一大堆 3.x 的文章，**而且標題不會告訴你**
- 兩層乘起來的後果：跑起來不對的時候，**你分不出是「翻錯了」還是「版本不對」**
- 這正是我在 C++ 吃過的虧的同一個形狀（每個範例都過時），只是這次有兩層

**三個選項攤開來看，才發現原本踩的是最貴的那個**

  | 選項 | 語言翻譯 | 版本翻譯 | 總翻譯稅 |
  |------|---------|---------|---------|
  | Unity + C# | 無 | 有 | **中** |
  | Godot + GDScript | 無 | 有 | 中 |
  | **Godot + C#**（原本） | **有** | 有 | **最高** |

- Godot 的母語是 GDScript，C# 是外掛的第二語言。**「一定要 C#」這個前提在 Godot 生態裡的代價，比在任何其他地方都高** —— 等於在一個講 GDScript 的國家裡堅持講 C#，然後抱怨沒有 C# 的路標。那是真的，而且不會改善

**一個被修正的判斷：黑箱數量 vs 黑箱可解性**

- 我原本的想法是「Godot 黑箱比較少所以比較好」。查下來**不成立** —— Unity 的黑箱其實**多很多**（Hub、授權、`Library` 快取、`.meta` 檔、序列化、Prefab、domain reload、asmdef、Mono vs IL2CPP、**三種渲染管線**）
- Unity 最惡名昭彰的那個：照著教學做，材質全變洋紅色，因為管線不一樣 —— 而教學裡通常不會寫。**跟「範例過時」是同一種痛**
- **但關鍵不是數量，是可解性**：

  | | 黑箱數量 | 撞到之後 |
  |---|---|---|
  | Unity | 多 | Google 三秒有答案，而且是 C# |
  | Godot + C# | 少 | 可能只有兩篇文章，一篇 3.x，一篇 GDScript |

- 我恨的那個東西 ——「**只能亂試的 debug**」—— 就是「黑箱 × 低可解性」的產物。**所以第二種比較差**

**一個技術上的自承**

- 我一直覺得「寫 code 跟擺物件不相容」，解釋兩次都沒被說服。查下來發現**我的直覺是對的，但原因是設定寫錯了**
- 原本用的是 `GetNodeOrNull<Marker2D>("Nest")` —— **用字串找節點**：打錯字編譯器不擋、改名不會壞在編譯時而是執行時、必須在腦中同時記住場景樹和程式碼
- Unity 的做法（`[SerializeField]` + 從 Inspector 拖一個物件進去）確實比較好：型別安全、沒有字串、改名不會壞
- Godot 其實也能做同樣的事（`[Export] public Marker2D Nest;`），只是原本選了比較差的那個模式。**這一條算設定的錯，不是引擎的錯**

**其他做完的事**

- **C# 教學 21 章**（`D:\CSharp`）：一章一個獨立的主控台專案，不是選單程式。每章有完整中文註解的 `Program.cs` + 三項「動手改」+ README（含實際跑出來的輸出）。第 21 章是主控台版的迷你蟻群，三條規則跟 Godot 版一字不差 —— **這一包跟引擎無關，完全保留**
- 工作區整理：根目錄從 31 項降到 19 項，`swarm1\` 放系統、`docs\` 放文件、`_tools\` 放腳本
- `環境配置.md`：13 節，含「壞掉時查這張表」（12 種症狀 → 先看哪裡）和「已驗證的事實」（六個被推翻的假設）
- Godot 那一線收成一包：引擎搬進 `D:\GodotTemplate\`，整條線自給自足，**保留不刪**，實測搬完之後仍然能一鍵產生可建置的專案
