# 2026-08-14 — 工作回報 #3：五天後推翻定案 → C++ 手寫路徑追蹤渲染器

## 今天讀/做了什麼

**上午（盤點 C++ 方向）**

- 起點是一個條件：要一條「**三年後打開專案，主迴圈裡還是自己寫的 C++**」的路
- 先弄清楚 C++ 方向是怎麼「後期沒有 C++」的，歸納出四種流失機制：**框架吸收**（Qt、Unreal，你寫的是框架方言）、**綁定層降級**（ML，C++ 被推到底層，日常在寫 Python）、**建置系統吞噬**（後期六成時間在 CMake 與連結錯誤）、**天花板**（三百行就寫完，根本沒有「後期」）
- 由此得到一條自檢法則：**三年後這個專案的最外層迴圈是誰在跑？** 如果是框架的 event loop 或編輯器，你就是填空的人
- 依此排除：Qt / Unreal（框架吸收）、ML（綁定層）、演算法與資料結構庫、HPC / SIMD（純 C++ 但零感官回饋，而且是「演算法當題目」不是當建材）、競技程式（紅線）
- 也排除了「**自己重寫一遍標準庫**」——它有公開規格、參考實作、難度遞增、無窮題目，看起來完美。但那組性質換個名字就是**刷題**：有標準答案、可對照、難度分階。而且驗收是 `static_assert` 綠了，零視覺回饋，卡住時只有兩百行模板錯誤訊息

**下午（定案 + 一次更底層的推翻）**

- 定案：**離線路徑追蹤渲染器**。它同時滿足四個條件——零依賴（一個 `.cpp` 加一個單檔頭）、無天花板、視覺回饋極強、**C++ 純度隨時間不降反升**（後期被逼到 SIMD、自訂配置器、靜態多型，因為沒有框架能幫你）
- 更關鍵的是把上一次定案為什麼失敗弄清楚了：**排斥 C# 不是因為它難，是因為「主迴圈不屬於自己」**。當時的原話是「有 Java 影子、有 CSS 的感覺」——**CSS 那個比喻抓到的其實是 inversion of control**：你只能宣告願望（設定屬性），不能追蹤機器怎麼做到的。`_Ready()` 是引擎呼叫你，不是你在跑
- 順帶釐清記憶體安全浪潮的實際範圍：它打的是**處理不信任輸入**的程式碼（協定解析、密碼學、OS 核心、檔案格式解碼），打不到**算力核心**（渲染、模擬、HPC、低延遲）。這兩塊在產業裡本來就是不同的人在寫
- 工具鏈定案 **VS 2026 + MSVC + MSBuild**，並拆掉一個常見誤解：**clang-cl 不需要 CMake**，它是專案屬性裡的一個下拉選單；**環境變數一個都不用設**，VS 建置時會自動注入開發者環境
- 建立效能的量級認知，避免為了小的去換大的摩擦：Release 對 Debug **10×**、多執行緒 **6–8×**、BVH **50–100×**、clang 換 MSVC 只有 **1.1–1.3×**。**演算法的量級碾壓編譯器的量級**
- 產出兩份文件：**S0–S13 課表**（每階都寫明「畫面上會看到什麼」＋可調旋鈕，附一張「**圖的症狀 → 病因**」對照表）、**環境安裝清單**（12 條卡住排除）
- 工作區從 `D:\Godot` 搬到 `D:\Render`，舊的三份設定檔全部降級成指路牌；新 repo：`github.com/anixwindy/Render`
