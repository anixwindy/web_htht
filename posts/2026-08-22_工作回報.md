# 2026-08-22 — 工作回報 #5：兩天後再次推翻定案 → 湧現模擬（模擬類遊戲開發）

## 今天讀/做了什麼

**上午（推翻 #4，而且這次換的不是題材，是「軸」）**

- 上一篇 `#4` 定案的 CP 維持了 **兩天**（前一次渲染器六天，再前一次 Godot 五天）。**累積 AC 題數：0**
- 推翻的理由很具體，是使用者自己講的三句話：

  | 他說的 | 對應的問題 |
  |---|---|
  | 「拆的技能大多都在理解&配置環境」 | 拆解的殘值高是真的，但**取得成本**沒被算進去，而他有設定摩擦過敏的前科 |
  | 「CP 想得出來還好，想不出來呢？沒有任何成品」 | CP 的回饋是**二元的**（AC / 不 AC），四小時想不出來的產出是 0 行 |
  | 「休假大腦身體都要打折」 | 需要一個**有檔位**的活動：巔峰時能鑽深，殘血時還能推進。CP 沒有低檔位 |

- **但真正的關鍵不在上面三句，在一句題外話**：

  > 「我好想當上帝……我玩星海 N 年，堅持做好每件事就是青銅；快攻＆中期換家可以到黃金白金，但是我喜歡前者。所有蟲都是我的，都聽我的。」

- 這句話的結構拆開來看：

  | 打法 | 性質 | 段位 | 選擇 |
  |------|------|------|------|
  | 快攻 rush | **直接型**：我現在就製造結果 | 黃金／白金 | 拒絕 |
  | 中期換家 | **直接型**：拆對面基地換勝負 | 黃金／白金 | 拒絕 |
  | 蟲族 macro「堅持做好每件事」 | **間接型**：顧經濟、注卵，軍隊自己長出來 | 青銅 | **打了 N 年** |

- 這是所有資料裡**唯一一筆「知道有更好的選項、算得出價差、然後選擇不拿」**的紀錄。
  前面四個 7–11 年的嗜好（爐石牧師 74%、MOBA 控制英雄、羽球只單打、單車只跑山）只證明他**喜歡**間接型；
  星海證明他**寧可輸兩三個段位也要待在間接位**。這條軸從偏好升級成硬約束
- 而它剛好解釋了四筆已經死掉的方向：

  | 做過的東西 | 間接性 | 結果 |
  |---|---|---|
  | 粒子系統（設重力／阻力／發射器，世界自己跑出算不到的東西） | 高 | ✅ 贏 |
  | raytrace（射一條光線 → 得一個顏色，一對一） | **零** | ❌ 主線活 6 天 |
  | 排序／尋路視覺化（照早就知道的方式跑完） | 零 | ❌ 輸 |
  | CP（想出解法 → AC，一對一，沒有東西在自己活） | **零** | ❌ 2 天 |

- 得到一條可以直接拿來擋掉未來提案的規則：

  > **只要「輸出 = 你輸入的直接函數」，這條線就會死。排任何東西前先問：有沒有東西在自己活？**

**中午（roguelike vs 開放世界，結論是兩個都不是）**

- 使用者問的原題是「roguelike 跟開放世界，code 跟遊戲內容差在哪」。核心差別只有一條：

  | | roguelike | 開放世界（手擺型） |
  |---|---|---|
  | 內容來源 | **規則 × 規則**（加第 21 個道具 = 新增 20 條交互，O(n²)） | **資產 × 人時**（加第 21 個地區 = +1，O(n)） |
  | 技術難點 | 組合正確性（純邏輯） | 規模管理（streaming／LOD／持久化／工具鏈） |
  | 團隊規模的現實 | Balatro 1 人、Slay the Spire 約 3 人 | Witcher 3 約 250 人 × 3.5 年 |

- 但用「當上帝」這把尺量，**兩個都不是最佳解**，因為它們的「玩」和「做」不是同一張椅子：

  | | 玩的時候你是誰 | 做的時候你是誰 |
  |---|---|---|
  | roguelike | **挑戰者**（在系統裡找一條鏈） | 上帝（設計系統） |
  | 開放世界（手擺） | 觀光客 | **手工藝人**（一格一格擺） |
  | **模擬／經營／自動化** | **上帝** | **上帝** ← 同一張椅子 |

- 而星海已經替他測過了：**他玩遊戲的時候選的就是上帝那張椅子**，選了 N 年，寧可輸段位
- 附帶解掉一個誤解：**「開放世界」有一種版本是成立的** —— Dwarf Fortress 開新世界會模擬幾百年歷史（板塊、河流、文明、戰爭、傳說），沒有人寫過那些故事，是跑出來的。那是**程序生成型**，兩兄弟做的，跟 250 人的手擺型完全是兩回事

- 第一個系統做完了：**蟻群覓食**。300 隻蟲，三條**在地**規則（每隻蟲只看得到自己周圍 34 px），使用者唯一能做的事是放食物，**不能命令任何一隻蟲**：

  ```
  規則 1  視野內有食物 → 走過去、抓一顆、掉頭
  規則 2  沒看到食物   → 前左／正前／前右各伸一根觸角，往濃的那邊轉
  規則 3  帶著食物     → 直線回巢，沿路留費洛蒙；費洛蒙指數衰減
  ```

- **意外**：蟲道。沒有任何一行程式碼寫著「形成蟲道」。更意外的是**改道** —— 近的那堆吃完之後，蟲群自己把主要蟲道搬到遠的那堆去，那個決策是費洛蒙衰減造成的，沒有程式碼指揮
- 為了能量化，加了 headless 實驗場（`lab.bat`，不開視窗只印數字，可帶參數）。跑出來的 A/B：

  | 條件 | t=35s 運回總數 | 速率 |
  |---|---|---|
  | 三條規則全開 | **569 顆** | **32.2 顆/秒** |
  | 關掉規則 2（不跟費洛蒙） | 204 顆 | 7.4 顆/秒 |

  **2.8 倍的效率差，來自六行程式碼**，而那六行裡沒有一個字提到「合作」「路徑」或「最佳化」

- 中間踩到一個很隱晦的坑，值得記下來：

  | | |
  |---|---|
  | 症狀 | headless 跑 15 秒，運回 **0 顆**，而且**完全沒有錯誤訊息** |
  | 誤判 | 以為模擬邏輯寫錯了 |
  | 真因 | `GetViewportRect().Size` 在 `--headless` 下回 **64×64**，不是專案設定的 1280×720。整個世界縮成一個小方塊，三堆食物全落在界外（負座標），蟲被困在角落 |
  | 修法 | 改成從 `ProjectSettings` 讀 `display/window/size/viewport_*` |
  | 副作用（正面） | 世界大小與視窗徹底脫鉤 → **同一個 Seed 保證同一場**，這是做 A/B 對照的前提 |

- **「上帝位耗盡」目前沒有解方，只有診斷。** 他在星海當上帝爽，是因為對手不受他控制；自己寫的模擬沒有對手，跑三次就看穿了。這就是為什麼 Factorio 要有蟲族來咬你、RimWorld 要有 story teller、Dwarf Fortress 的座右銘是 "Losing is Fun"。規劃裡把整個第三年都押在這一題上，但那是三年後的事，**中間兩年沒有防護**
- 一個結構性的死穴：**單人開發者無法對自己的系統做有效的 playtest**，因為你知道所有的規則、所有的機率、所有的組合。「你砍不破自己系統的那天」在單人開發下**數學上不會到來**。唯一的解是把東西丟給別人玩，而那要等到很後面
